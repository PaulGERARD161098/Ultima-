## Constats sécurité (S)

### S1 — supabase-js chargé d'un CDN sans SRI ni version épinglée (supply chain)
- **Où** : `index.html` (script `cdn.jsdelivr.net/npm/@supabase/supabase-js@2`).
- **Constat** : version flottante `@2` + aucun attribut `integrity`. Le fichier
  `.min.js` est auto-minifié par jsdelivr (octets non garantis) : un CDN compromis
  ou un poisoning = exécution JS arbitraire (XSS total), CSP inopérante puisque
  l'origine est autorisée dans `script-src`.
- **Correctif** : vendoriser le bundle UMD officiel npm `2.110.0` (déjà minifié
  par l'éditeur) dans `js/vendor/`, servir en same-origin, retirer
  `cdn.jsdelivr.net` de la CSP.
- **Test de fermeture** : mode démo et chargement client OK en navigateur ;
  CSP sans jsdelivr.

### S2 — `search_path` mutable sur `public.set_updated_at` (advisor 0011, WARN)
- **Où** : fonction trigger créée par la migration 0001.
- **Constat** : fonction sans `search_path` fixé → résolution d'objets détournable
  par un rôle pouvant créer des objets dans un schéma prioritaire.
- **Correctif** : migration `0002` — `alter function … set search_path = ''`.
- **Test de fermeture** : advisor security ne remonte plus le lint.

### S3 — IP de rate-limit dérivée de `x-forwarded-for` en priorité
- **Où** : `middleware.js` (`clientIp`).
- **Constat** : XFF est réécrit par Vercel en pratique, mais `x-real-ip` (posé par
  la plateforme, mono-valeur) est la source la plus sûre ; défense en profondeur
  contre un contournement du rate-limit par en-tête forgé.
- **Correctif** : privilégier `x-real-ip`, garder XFF en repli.
- **Test de fermeture** : revue de code (non reproductible hors plateforme).

### S4 — corps JSON lu en flux sans plafond de taille
- **Où** : `api/_lib/http.js` (`readJsonBody`).
- **Constat** : concaténation de chunks sans limite applicative (la limite Vercel
  ~4,5 Mo reste large pour du JSON de ce contrat).
- **Correctif** : plafond 100 Ko → rejet `413`.
- **Test de fermeture** : corps > 100 Ko rejeté sans parsing.

### S5 — policies RLS ré-évaluent `auth.uid()` par ligne (advisor 0003, WARN ×8)
- **Où** : 8 policies des tables `network_nodes` / `network_edges`.
- **Constat** : `auth.uid()` non encapsulé → initplan ré-évalué par ligne,
  dégradation à l'échelle (surface RLS : traité en rigueur maximale).
- **Correctif** : migration `0003` — `(select auth.uid())` dans les 8 policies
  (comportement identique, périmètre d'accès inchangé).
- **Test de fermeture** : advisor performance ne remonte plus le lint.

### S6 — CSP `connect-src https://*.supabase.co` trop large
- **Où** : `middleware.js` (CSP).
- **Constat** : wildcard = un XSS résiduel pourrait exfiltrer vers n'importe quel
  projet Supabase tiers.
- **Correctif** : restreindre au domaine du projet
  `https://leosfqyidgsaescjbfom.supabase.co`.
- **Test de fermeture** : en-tête CSP restreint, appels app fonctionnels.

## Constats UX / fonctionnels (U)

### U1 — écriture en mode connecté impossible : `owner_id` jamais renseigné (bloquant)
- **Où** : `api/reseau/nodes.js`, `api/reseau/edges.js` × migration 0001.
- **Constat** : l'API n'envoie pas `owner_id` (choix sain) mais la colonne est
  `NOT NULL` **sans défaut** : tout INSERT échoue (23502) avant même la RLS.
  Le commentaire « owner_id imposé par la RLS » est faux : une policy vérifie,
  elle ne remplit pas.
- **Correctif** : migration `0004` — `owner_id default auth.uid()` sur les
  2 tables (motif Supabase standard ; la policy `WITH CHECK` reste la garantie).
- **Test de fermeture** : défaut visible au schéma ; création visée au premier
  usage connecté réel.

### U2 — champs optionnels vides bloquent la création (email `''` → « Email invalide »)
- **Où** : `js/app.js` (`soumettreFormNoeud`) × `api/_lib/validate.js`.
- **Constat** : le front envoie `''` pour tout champ vide ; l'API rejette `''`
  pour l'email → impossible de créer un nœud sans e-mail en mode connecté.
- **Correctif** : en création, omettre les champs optionnels vides ; en édition,
  envoyer `null` (vidage effectif, accepté par la validation).
- **Test de fermeture** : payloads vérifiés (création sans email OK, édition
  vidant un champ OK).

### U3 — PATCH d'un nœud inexistant/non possédé → 500 au lieu de 404
- **Où** : `api/reseau/nodes.js` (`.single()` sur UPDATE).
- **Constat** : 0 ligne (RLS ou id inconnu) → erreur PGRST116 → « Erreur
  interne » trompeuse (DELETE utilise déjà `maybeSingle()` correctement).
- **Correctif** : `maybeSingle()` + 404 sur `null`.
- **Test de fermeture** : revue + symétrie avec DELETE.

### U4 — brancher Supabase réel (roadmap site n°1)

- **Constat** : config vide = mode démo permanent.
