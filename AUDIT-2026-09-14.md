# Audit correctif du 14 septembre 2026

## Cadrage avant correction

1. But : corriger les défauts reproduits dans le dépôt Ultima et livrer une branche vérifiée, avec les limites de validation explicites.
2. Étapes : état de référence GitHub, lecture API/front/SQL, contrôle Supabase en lecture seule, reproductions, correctifs, tests existants et tests de régression, pull request.
3. Moyens : sources du commit `3811b123f60450882b8125a338e0557eda96c7aa`, Node 24, navigateur Chromium, schéma et advisors Supabase. Les 396 fichiers texte récupérés ont été vérifiés contre leurs empreintes GitHub.
4. Réussite : chaque constat corrigé dispose d'une reproduction ou d'un contrôle exécutable ; les tests concernés passent ; le diff publié correspond au code vérifié.
5. Périmètre : code et migrations préparées. Pas de changement de comptes, de secrets, de données métier en production, ni d'envoi réel de mail ou de contenu à Google/Anthropic.
6. Risques : erreurs silencieuses, réponses tardives après déconnexion, courses de sauvegarde, limites de pagination, suppressions partielles, fichiers privés déployés. Vérification des chemins d'échec et de refus, sans assouplir les protections pour satisfaire un test.

## Résultat et périmètre

Correctifs préparés sur `fix/audit-2026-09-14` à partir de
`3811b123f60450882b8125a338e0557eda96c7aa`. **36/36 suites unitaires et
41/41 harnais navigateur passent.** Les changements comprennent une migration
qui doit précéder le déploiement du code. Aucune migration ni donnée métier de
production n'a été modifiée pendant cet audit.

Le dépôt a été lu sur ses axes API, authentification, middleware, intégrations,
front, schéma SQL, configuration et tests. Ce rapport porte sur les défauts
confirmés et les contrôles exécutés ; il ne certifie pas l'absence de tout défaut
possible ni le fonctionnement des services externes avec des comptes réels.

## Vérifications et éléments ayant résisté

- **Référence** : 396 fichiers texte contrôlés contre les SHA de blobs GitHub ;
  le PDF embarqué dans une compétence n'a pas été édité. Les 33 suites unitaires
  présentes à l'ouverture passaient déjà : elles ne couvraient pas les défauts
  ci-dessus.
- **Unitaires finaux** : `npm test`, **36/36**. Les trois nouvelles suites
  invoquent les handlers avec transports contrôlés, éprouvent les délais et
  rejouent les **27 fichiers de migration** dans PGlite. Seule adaptation locale :
  retirer l'installation de l'extension `pgcrypto`, inutilisée par ces migrations ;
  `gen_random_uuid()` est natif.
- **Navigateur** : **41/41** fichiers `smoke-*.mjs`, sous Chromium 153 et Node
  24.19.0. Exécution du harnais global complétée par les parcours manquants puis
  les reprises ciblées de VRANESH et de la capture après correction. Ce chiffre
  est l'union des journaux d'exécution, pas l'annonce d'une exécution globale
  sans interruption. Les tests simulent les API avec des données factices.
- **Syntaxe** : 82 fichiers runtime API/JS/middleware contrôlés ;
  `git diff --check` sans erreur. `npm audit` final : **zéro vulnérabilité
  signalée**, dépendances de développement comprises, à la date du contrôle.
- **Supabase réel, lecture seule** : les **28 tables publiques** ont la RLS ;
  les **10 vues** sont `security_invoker=true`. Les FK RIVEN de la migration
  0025 sont déjà présentes : ne pas rejouer cette ancienne action sur la foi
  des notes historiques. Les références fautives D3/D4 ont été vérifiées dans
  le catalogue PostgreSQL, sans lire de contenu métier.
- **Refus éprouvés** : un deuxième compte ne voit pas la situation du premier,
  ne la dénoue pas, et ne peut y rattacher ses références ; le rôle `anon` ne
  peut appeler la RPC. Les pages sans session, portes publiques, filtres et
  protections de contenu du patrimoine restent couverts par les anciens tests.

Le téléchargement du navigateur Playwright et le démarrage du daemon
agent-browser n'ont pas abouti dans cet environnement. Le harnais Playwright du
dépôt a donc été exécuté avec un Chromium fourni localement. Cela vérifie le DOM
et les parcours ; cela ne vérifie pas les décisions de routage du CDN Vercel.

## Migration : ordre de livraison obligatoire

Fichier préparé :
`supabase/migrations/20260914142755_audit_integrite_et_denouement.sql`.

1. Obtenir le go requis par `CLAUDE.md` pour la migration de production et la
   fusion. La demande d'audit/patch autorise la préparation du correctif ; aucune
   de ces deux opérations de production n'a été exécutée.
2. Revérifier le projet Ultima, les définitions de contraintes et les deux
   compteurs ci-dessous. Appliquer **uniquement cette nouvelle migration**, après
   réconciliation de l'historique Supabase : les noms historiques utilisent une
   ancienne numérotation, dont deux fichiers `0020`.
3. Contrôler les contraintes, les droits RPC et les advisors après application.
   La migration est transactionnelle, avec délais de verrou et d'instruction ;
   elle échoue sans nettoyage automatique si des liens incompatibles existent.
4. Fusionner puis déployer le code. Sans RPC, le dénouement renvoie **503** et
   ne revient jamais à la coupe non atomique. Les autres opérations conservent
   leurs contrats.
5. Vérifier sur le déploiement les refus des chemins privés et un parcours
   authentifié avec un jeu de données de test autorisé.

Précontrôle exécuté le 14/09 : **0 / 0**. Requête reproductible :

```sql
select 'idees_liens' as controle, count(*) as violations
from public.idees_liens l
join public.idees s on s.id = l.source_id
join public.idees t on t.id = l.target_id
where l.owner_id <> s.owner_id or l.owner_id <> t.owner_id
union all
select 'intendant_fournisseur', count(*)
from public.intendant_besoins b
join public.network_nodes n on n.id = b.fournisseur_node_id
where b.owner_id <> n.owner_id;
```

Le retour à l'ancien code reste possible après cette migration : elle conserve
les colonnes et les tables. Ne pas retirer les contraintes ou recréer les FK
incorrectes pour effectuer un rollback applicatif. Une coupe de scénarios est
une action métier déjà destructive avant cet audit ; la RPC la rend atomique,
elle ne constitue pas une sauvegarde des branches supprimées.

## Limites et actions restantes

- **Production** : pas de fusion, migration, déploiement, connexion Google réelle,
  appel Anthropic ou mail réel pendant l'audit. Les permissions du plugin et les
  tests locaux ne prouvent pas un déploiement réussi. Le résultat de la CI devra
  être lu sur la PR une fois celle-ci publiée.
- **Ancien brouillon** : la clé locale `ultima-maedrethnir-brouillon`, dépourvue
  de propriétaire, reste intacte. Sa récupération doit être manuelle sur le
  navigateur d'origine après identification de son auteur ; il serait incorrect
  de l'attribuer automatiquement au prochain compte. Les nouveaux brouillons
  utilisent le suffixe `:<user.id>`. Le stockage local ne protège pas contre une
  personne ayant accès au même profil de navigateur.
- **Accusé de réception perdu** : le verrou empêche les envois simultanés dans la
  page, pas tous les doublons après un rechargement si le serveur a écrit mais
  que sa réponse a été perdue. Une identité de capture persistante et une
  contrainte d'idempotence en base seraient nécessaires pour garantir ce cas.
- **Pagination** : les pages sont ordonnées mais ne constituent pas un snapshot
  transactionnel unique ; des modifications concurrentes peuvent faire bouger
  les offsets. Le plafond explicite est de 50 000 lignes par collection.
- **Limitation de trafic** : le garde reste local à une instance Vercel, il ne
  fournit pas un quota global entre instances.
- **Advisor Supabase** : la protection contre les mots de passe divulgués est
  désactivée. C'est un réglage Auth, pas une correction de fichier ; aucun réglage
  de compte ou de plan n'a été changé. Le produit utilise actuellement lien
  magique/Google. Le signalement historique de rotation de `CRON_SECRET` dans
  FINUBAR reste une action humaine ; sa résolution n'a pas été vérifiée ici.
- **Historique et intégrations de pilotage** : pas de collecte des sept autres
  dépôts non attachés ni de synchronisation Notion. Les jalons produit antérieurs
  ne sont pas annoncés comme remesurés par cet audit de code.
